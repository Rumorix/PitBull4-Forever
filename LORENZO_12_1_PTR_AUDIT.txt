PitBull4 12.1 API / Spell-ID Audit - Patch 034
Reviewed live UI source baseline: 12.1.0.69299
Direct predecessor: Patch 033 / FortifyingBrewAuraAlias

Change boundary
---------------
Patch 034 changes only MajorCooldownAuras built-in spell candidate lists,
public cast-to-aura alias tables, diagnostics, metadata, and documentation.
It does not change Blizzard protected container APIs, protected state-driver
lifecycle, ImportantDebuffs, normal Aura rendering, tooltip policy, PowerBar,
player-resource pings, or dynamic target/focus refresh.

Aura identity contract
----------------------
- Options and saved per-spell settings remain keyed to familiar spellbook/cast
  IDs.
- Static public alias tables expand an enabled configuration ID into known
  public active-aura IDs before assigning includeSpellIDs to Blizzard's
  protected AuraContainer.
- PitBull never reads an assigned aura to discover or validate that mapping.
- Cast IDs are retained in the candidate set for compatibility with client/spec
  variants that may expose the same ID as the active aura.
- Custom user-entered offensive IDs remain direct aura IDs and are not remapped.

---------------------

behavior proves it should be represented, it requires a separately reviewed

Regression contract
-------------------
- Fortifying Brew 115203/120954 must continue to match.
- Patch 028 must still prevent RegisterStateDriver construction/replacement in
  combat and reconcile deferred state only after PLAYER_REGEN_ENABLED.
- Patch 031 dynamic AuraContainer refresh must remain unchanged.
- Patch 032 player-resource ping behavior must remain unchanged.
- Major Cooldown Auras and Important Debuffs must remain separate.
- No protected/secret aura values may be compared, formatted, used as keys, or
  converted to addon control-flow booleans.
- No SavedVariables migration is required.
